How your data is protected

        
Every task is encrypted on this device with AES-256-GCM before it
          ever touches storage. The key that does that encryption is derived from your passphrase
          and never leaves your browser — it's never sent anywhere, not to us, not to a server,
          not to anyone. IndexedDB, this browser's local database, holds only what you see below:
          an ID, a random IV, ciphertext, and a timestamp. If sync is ever turned on, that's also
          the only thing that would ever be sent — the exact same ciphertext already sitting here.

        
        

      

    


    

      

        
Verify your task history

        
Every time a task is added, edited, or deleted, Haven signs a
          record of it with a key that lives only on this device and chains it to the record
          before it — like a private, personal git log. If anything in that log were ever silently
          altered, this check would catch it: a broken link in the chain, or a signature that
          doesn't match, shows up immediately below. This runs entirely on your device against
          your local history — nothing is uploaded to check it.

AI assistant

        
A small language model that runs entirely in your browser — it
          never sends a task, a title, or a note anywhere. Off by default: nothing downloads until
          you click Enable below. The download (about 140MB, once) does need the internet; after
          that, generating an answer is a local computation with zero network requests, even
          offline. It's genuinely small, so answers are useful but plain-spoken, not polished —
          and on this device it takes roughly a minute per answer, not a few seconds.

    Social recovery
    

    
    
      
    
        Split your recovery code into pieces you give to people you trust. Any of them, working
        together — enough to reach the threshold you choose — can help you back in if you ever
        forget your passphrase and lose the code. Nobody, not even you, can read the pieces alone
        or reconstruct anything to give it to anyone else.
      
    
      
    
        
        
      
    
      
    
        
    
          
          
        
    
        
    
          
          
        
    
      
    
      
    
      
    
        
        
      
    
    
    

    
    
      
    
        Give each share below to a different person, over a different channel if possible (one by
        text, one in person, one by email) — copy each one individually. Once you close this, these
        exact shares won't be shown again; generate a new set instead if you lose track of one.
      
    
      
    
      
    
        
      
    
    
    
  
    

    


    
  
    
    
    Unlock with a passkey
    

    
    
      
    
        Add a passkey (Touch ID, Windows Hello, or a hardware security key) as a faster way to
        unlock — your passphrase still works too, and still is what protects the actual encryption
        key underneath. Needs an authenticator that supports resident keys and encrypted storage
        (most modern platform authenticators do); if yours doesn't, you'll get a clear error and
        nothing will be changed.

    Set up a decoy vault
    
    
    
      Pick a second passphrase. Entering it on the lock screen opens a completely separate,
      normal-looking vault instead of this one — nothing in the app shows which one is open, so
      it's worth adding a few plausible tasks to the decoy so it holds up to a glance.
    
    
    
    
      
      
    
    
    
    
      
      
    
    
    
    
      Use a different passphrase than your real one. This doesn't sync to other devices and has no
      recovery code — lose this passphrase and the decoy vault's contents are gone for good, same
      as losing both your real passphrase and recovery code would be for this vault. Running this
      again replaces the decoy vault entirely, including anything already in it.

      for one to set off an endless loop of another.

    Sync (optional)
    

    
    
      
    Sync keeps tasks in step across your devices through a server that only
        ever stores ciphertext — same guarantee as this device, nothing new to trust. Leave the
        token blank to start a fresh, empty bucket, or paste one from a device you've already set
        up to join it.
    
      
    
        
        
      
    
      
    
        
        
      
    
      
    
        
    Joining an existing bucket needs the recovery code from the device
          that started it — that's what lets this device decrypt the same tasks, not the token
          alone. Your passphrase on this device doesn't change; confirming it just re-locks the
          shared key under it.
    
        
    
          
          
        
    
        
    
          
          
        
    
      
    
      
    
      
    
    

    
    
      
    Sync is on. This token is a bearer capability for your ciphertext bucket
        — anyone who has it can read and write it, so treat it like a password. Enter this same
        server and token on another device, along with your recovery code, to sync between them —
        your recovery code now unlocks this synced task list on any joined device, not just this
        one, so it's worth treating with the same care.
